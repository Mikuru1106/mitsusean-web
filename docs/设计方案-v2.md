# 水聖安粉丝站 · V2 设计方案

> 版本:v2 提案 / 2026-08-28
> 目标:延续现有「水系粉色」视觉语言,升级为内容更丰富、带数据监测能力的个人主页。

---

## 一、设计理念与风格延续

保持现有 Design System 不变,只做延伸:

| 元素 | 现状 | V2 处理 |
|---|---|---|
| 配色 | 樱粉 `#FF8FAB` / 玫瑰 `#B76E79` / 墨色 `#241322` / 底色 `#DFDFF0` | 全部保留;新增数据区「观测舱」深色面板(沿用抽奖机屏幕的 `#1A1018 → #241322` 渐变 + 粉色霓虹) |
| 字体 | Zentry(巨型标题)/ General Sans(正文) | 保留;数字仪表使用 JetBrains Mono 增加仪表感 |
| 组件语言 | 玻璃卡片 `card`、`glass-tag`、`gradient-text`、bento 网格 | 保留并复用 |
| 动效 | AnimatedTitle 逐词入场、float 悬浮、滚动视差 | 保留;数据区新增 count-up 数字滚动与曲线绘制动画 |
| 主题意象 | 水(💧)、清泉、流动 | 升级为「水的感觉贯穿数据」:曲线像水波、卡片带水光渐变 |

一句话:**像把现有站点放进一个「粉丝观测站」,数据是新的水滴,汇成湖面。**

## 三、核心模块设计

### 1. Hero 首屏(微调)

- 保留巨型 Zentry 标题 + 水滴浮动。
- 右上角新增 **实时徽章**(glass-tag 样式):
  `● LIVE · 粉丝 12,345 · 数据更新于 08-28`
  数字接入数据模块同一数据源,带 count-up 入场。

### 2. 歌曲切片馆(升级)

现有 6 条静态列表升级为「陈列馆」:

- **顶部工具栏**(glass-tag 风格):
  - 分类筛选:`全部 / 翻唱 / 歌回切片 / 合唱`
  - 排序:`最新 / 最热`
- **卡片**(沿用 `ai-plaza-card` 骨架):
  - 封面占位图(无封面时用水波纹渐变 + 💧)
  - 标题、日期、简介、`▶ 播放` 角标
  - hover:卡片上浮 + 封面水波纹扫过(GSAP)
- **点击弹出播放层**:内嵌 B 站 iframe 播放器(bvid 存在时),否则跳转链接;玻璃遮罩 + 圆角容器,风格统一。
- 数据补充:每张卡片右上角显示播放量小字(来自数据模块缓存)。

### 3. B站数据观测舱 ★(全新核心模块)

整块使用**深色观测舱面板**,视觉上呼应抽奖机屏幕,形成深浅节奏:

```
┌─────────────────────────────────────────────┐
│  SOURCE OBSERVATORY · 数据观测舱   [更新于…] │
│ ┌─────────┬─────────┬─────────┬─────────┐  │
│ │ 粉丝数   │  总播放  │  总获赞  │  稿件数  │  │
│ │ 12,345  │ 98.7万  │  5.6万  │   128   │  │
│ │ ↑ +42/日 │ (水波线) │         │         │  │
│ └─────────┴─────────┴─────────┴─────────┘  │
│ ┌───────────────────┬───────────────────┐  │
│ │  粉丝增长曲线      │   涨粉热力图       │  │
│ │  (30/90天切换)     │   (近90天格状)     │  │
│ └───────────────────┴───────────────────┘  │
│ ┌─────────────────────────────────────┐    │
│ │  近期切片表现(播放/点赞/投币 条形)     │    │
│ └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

细节设计:

- **四张数据卡**:深色玻璃卡(`bg-white/6` + 霓虹描边),大数字 JetBrains Mono,count-up 动画;每卡下方一行趋势小字(`较昨日 +42` 绿色/红色)。
- **粉丝增长曲线**:SVG 面积图,粉色渐变填充 + 发光描边,曲线缓慢"绘制"入场动画(像水流铺开);30 天 / 90 天 / 全部 切换。
- **涨粉热力图**:GitHub 贡献图风格,5×18 格子,颜色从 `#FF8FAB` 透明度分 5 档;hover 显示当日净涨粉。
- **近期切片表现**:横向条形列表(标题 + 三色小条:播放/点赞/投币),与切片馆数据打通。
- **数据说明脚注**:`数据来自 B站公开接口,由站点定时快照,仅供参考`。
- 移动端:四卡 2×2,图表纵向堆叠。

### 4. 粉丝里程碑(全新)

垂直时间轴(卡片式,左右交替):

- 节点类型:`首播 / 万粉达成 / 爆款切片 / 周年`
- 每个节点:日期 + 标题 + 一句话 + 可选配图
- 滚动进入视口时逐节点浮现(GSAP ScrollTrigger,与现有动效一致)
- 数据自动补位:如「粉丝突破 1 万 · 2026-xx-xx」可由数据历史 JSON 自动生成

### 5. 声音按钮 / 抽奖机 / 页脚

- 声音按钮:保留,补上音频文件加载失败的静默降级。
- 抽奖机:保留,奖品池可接入「里程碑文案」增加趣味。
- 页脚:新增一行 `数据快照更新于 YYYY-MM-DD HH:mm`。

## 四、B站数据监测:数据来源方案(关键决策)

站点为纯静态前端,无后端。三种方案:

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 构建期快照(推荐)** | GitHub Actions 每天 1 次跑 Node 脚本,请求 B站公开接口,把当天数据 append 到 `data/history.json` 提交进仓库 | 零运维、自带历史曲线、CORS 无忧 | 依赖部署在 GitHub;接口偶有风控需重试 |
| B. 本地实时代理 | dev 时用 Vite middleware 代理 B站接口取实时值,历史仍存 JSON | 数据最新 | 生产环境 CORS 受限,只适合本地 |
| C. 手动维护 | 手动编辑 JSON | 最简单 | 无法坚持,曲线会断 |

**推荐 A + B 混合**:仓库内 `history.json` 提供历史曲线(A);前端加载后若本地 dev 或接口可达,再拉一次实时数覆盖「今日」快照(B)。接口建议使用 `space.bilibili.com` 的公开 card/stat 接口(mid=431115683),脚本内固定 UA + 失败重试 + 快照去重。

数据文件结构:

```jsonc
// data/history.json
{
  "updated": "2026-08-28T09:00:00+08:00",
  "snapshots": [
    { "date": "2026-08-01", "followers": 11890, "views": 960000, "likes": 52000, "videos": 121 },
    // ...每日一条
  ]
}
```

## 五、技术选型

- 保持 **React + Vite + TypeScript + Tailwind** 不变。
- 图表:**自绘 SVG**(面积图/热力图/条形),与现有动效体系最贴合、零新依赖;数字滚动用现有 GSAP。
- 动效:GSAP ScrollTrigger(已在依赖中)。
- 数据层:`src/data/history.json` + 轻量 `useBiliStats()` hook(合并快照 + 实时兜底 + localStorage 缓存)。

## 六、实施计划(建议分期)

1. **P1 静态骨架**:观测舱 UI + 假数据接口、切片馆升级、里程碑时间轴(纯前端)
2. **P2 数据真实化**:快照脚本 + history.json + count-up/曲线动画
3. **P3 打磨**:播放弹层、实时兜底、移动端适配、性能与降级
