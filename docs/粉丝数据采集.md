# 粉丝数据采集(zeroroku 式每日快照)

参照 [Jannchie/zeroroku](https://github.com/Jannchie/zeroroku) 的架构复刻:
**后台定时采集 → 持久化每日快照(含 rate1/rate7) → 前端只读展示**。

## 组成

| 部分 | 文件 | 说明 |
|---|---|---|
| 采集器 | `scripts/snapshot.mjs` | 请求 `x/relation/stat` 获取实时粉丝数,计算 rate1(日涨粉)/rate7(7日涨粉),写入当日快照 |
| 存储 | `public/data/fans-history.json` | 每日一条 `{ date, followers, rate1, rate7 }`,由采集器追加/更新 |
| 前端 | `src/hooks/useBiliStats.ts` | 运行时加载 JSON,失败回退 `src/data/history.ts` 静态表;实时粉丝数仍覆盖最新点 |
| 展示 | `src/components/Observatory.tsx` | 粉丝卡片显示 `日涨粉 · 7日涨粉`(zeroroku 的 rate1/rate7) |

## 手动执行

```bash
npm run snapshot
```

输出示例:

```
✓ 2026-09-02 粉丝 175873 | rate1=578 rate7=- | 快照总数 96
```

## 定时任务

采集器必须由定时任务每天运行一次；前端不会自行生成历史日期。仓库已提供 `.github/workflows/snapshot.yml`，会在北京时间每天 09:00 自动采集、提交 JSON，并触发部署流程；也可以使用下面的 Windows 任务计划程序。

### Windows 任务计划程序

```powershell
# 在项目目录执行，每天上午 9:00 运行
schtasks /create /tn "MizuseanSnapshot" /tr "cmd /c cd /d C:\\path\\to\\mitsusean-web && npm run snapshot" /sc daily /st 09:00
```

### Linux / GitHub Actions(cron)

工作流使用 `0 1 * * *`（UTC 01:00，即北京时间 09:00），并支持 `workflow_dispatch` 手动补采。每次成功运行会把 `public/data/fans-history.json` 提交回仓库；首次启用后，从实际采集当天开始每天新增一条真实记录。


## 数据真实性边界

- B 站接口只返回**当前**粉丝数,没有任何历史接口;
- 历史曲线从**开始采集之日**起逐日累积为真实数据;
- `2026-08-31` 之前的数据是演示数据(基准已锚定到真实量级),会在 JSON 中永久保留用于曲线连续性;
- zeroroku 的完整历史也是因为它后台采集器运行了很久。
