# 数据每日采集(zeroroku 式快照)

参照 [Jannchie/zeroroku](https://github.com/Jannchie/zeroroku) 的架构复刻:
**后台定时采集 → 持久化每日快照 → 前端只读展示**。

粉丝数使用免登录公开接口;总播放、总获赞、稿件数与 B 站个人主页展示一致,需要登录 Cookie,
由 Chromium 带 Cookie 打开个人主页读取(与个人主页顶部统计卡同源)。

## 组成

| 部分 | 文件 | 说明 |
|---|---|---|
| 采集器 | `scripts/snapshot.mjs` | 粉丝数走公开接口;播放/获赞/稿件用 Playwright 打开个人主页读取;计算 rate1/rate7 并写入当日快照 |
| 浏览器 | `playwright` + chromium | 需在运行环境安装 chromium(本地 `npx playwright install chromium`,GitHub Actions 自动安装) |
| 存储 | `public/data/fans-history.json` | 每日一条 `{ date, followers, views, likes, videos, rate1, rate7 }`,由采集器追加/更新 |
| 前端 | `src/hooks/useBiliStats.ts` | 运行时加载 JSON,优先使用真实采集的播放/获赞/稿件;缺失时回退静态表 |
| 展示 | `src/components/Observatory.tsx` | 粉丝卡片显示日涨粉、7日涨粉及三项总量 |

## 手动执行

```bash
# 首次先安装 Chromium
npx playwright install chromium

npm run snapshot
```

设置 `BILI_COOKIE` 后可采集播放/获赞/稿件:

```text
BILI_COOKIE="SESSDATA=...; bili_jct=...; buvid3=..." npm run snapshot
```

输出示例:

```text
✓ 2026-09-05 粉丝 177499 | rate1=- rate7=- | 播放 1234567 获赞 89012 稿件 120 | 快照总数 3
```

未设置 Cookie 或读取失败时,播放/获赞/稿件记为 `-`,采集器仍会正常记录粉丝数(降级不影响每日任务)。

## 定时任务

采集器必须由定时任务每天运行一次;前端不会自行生成历史日期。仓库已提供 `.github/workflows/snapshot.yml`,
会在北京时间每天 09:00 自动安装依赖与 Chromium、采集、提交 JSON,并触发部署;也支持手动触发。

### GitHub Actions Secret

在仓库 **Settings → Secrets and variables → Actions** 中新建仓库 Secret:

- 名称:`BILI_COOKIE`
- 值:从已登录 B 站浏览器复制的完整 Cookie 字符串(至少包含 `SESSDATA`,建议同时包含 `bili_jct`、`buvid3`)

工作流通过 `${{ secrets.BILI_COOKIE }}` 注入采集器,Cookie 不会写入代码或日志。Cookie 过期后需重新更新 Secret。

## 数据真实性边界

- B 站接口/页面只返回**当前**数据,没有历史接口;
- 历史曲线从**开始采集之日**起逐日累积为真实数据;
- `2026-08-31` 之前的数据是演示数据(基准已锚定到真实量级),会在 JSON 中永久保留用于曲线连续性;
- 播放/获赞/稿件需登录态,若 Cookie 失效或被风控,当天这三项可能为空,粉丝数不受影响。
