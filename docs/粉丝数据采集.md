# 数据每日采集(zeroroku 式快照)

参照 [Jannchie/zeroroku](https://github.com/Jannchie/zeroroku) 的架构复刻:
**后台定时采集 → 持久化每日快照 → 前端只读展示**。粉丝数使用公开接口；总播放、总获赞、稿件数需要配置 B 站登录 Cookie。

## 组成

| 部分 | 文件 | 说明 |
|---|---|---|
| 采集器 | `scripts/snapshot.mjs` | 请求 B 站接口获取粉丝、播放、获赞、稿件数，计算 rate1(日涨粉)/rate7(7日涨粉)，写入当日快照 |
| 存储 | `public/data/fans-history.json` | 每日一条 `{ date, followers, views, likes, videos, rate1, rate7 }`，由采集器追加/更新 |
| 前端 | `src/hooks/useBiliStats.ts` | 运行时加载 JSON，优先使用真实采集的播放/获赞/稿件；缺失时回退静态表 |
| 展示 | `src/components/Observatory.tsx` | 粉丝卡片显示日涨粉、7日涨粉及三项总量 |

## 手动执行

```bash
npm run snapshot
```

输出示例:

```text
✓ 2026-09-02 粉丝 175873 | rate1=578 rate7=- | 播放 1234567 获赞 89012 稿件 120
```

播放/获赞/稿件为真实值的前提是设置 `BILI_COOKIE` 环境变量；未设置时采集器仍会记录粉丝，其他三项写为空值，前端继续回退旧静态值。

## 定时任务

采集器必须由定时任务每天运行一次；前端不会自行生成历史日期。仓库已提供 `.github/workflows/snapshot.yml`，会在北京时间每天 09:00 自动采集、提交 JSON，并触发部署流程；也可以使用下面的 Windows 任务计划程序。

### Windows 任务计划程序

```powershell
# 在项目目录执行，每天上午 9:00 运行
schtasks /create /tn "MizuseanSnapshot" /tr "cmd /c cd /d C:\\path\\to\\mitsusean-web && npm run snapshot" /sc daily /st 09:00
```

### GitHub Actions Secret

在仓库 **Settings → Secrets and variables → Actions** 中新建仓库 Secret：

- 名称：`BILI_COOKIE`
- 值：从已登录 B 站浏览器复制的完整 Cookie 字符串（至少包含 `SESSDATA`，建议同时包含 `bili_jct`、`buvid3`）

工作流会通过 `${{ secrets.BILI_COOKIE }}` 注入采集器，Cookie 不会写入代码或日志。Cookie 过期后需重新更新 Secret。


## 数据真实性边界

- B 站接口只返回**当前**粉丝数,没有任何历史接口;
- 历史曲线从**开始采集之日**起逐日累积为真实数据;
- `2026-08-31` 之前的数据是演示数据(基准已锚定到真实量级),会在 JSON 中永久保留用于曲线连续性;
- zeroroku 的完整历史也是因为它后台采集器运行了很久。
